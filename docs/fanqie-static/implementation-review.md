# 番茄视频静态分析与实现前置核对

核对日期：2026-11-11。本文记录实现前置评估与已确认目标：利用番茄官方实现核对修复现有红果播放，不新增独立番茄入口。静态和离线检查不表示实播成功。

## 分支与隔离

- 独立分支：`fix/hongguo-playback-fanqie-analysis`。
- 起点：重新取得的 `origin/main`，`805f747`。
- 现有 `fix/android-source-timeout-budget` 工作树及其未提交修改保留；仅选择性移植其中预算修复及对应测试，不整体合并旧分支。
- 用户已明确本轮利用番茄协议分析修复现有红果播放。下文新来源隔离风险仅为分析记录，不新增入口或更换红果应用身份。

## 实现边界

仅接受正常授权响应。静态包中存在接口、字段或播放器类，不代表服务器允许匿名访问，不代表某个剧集免费、完整或未加密，也不证明对应路径仍是运行时首选。

不因一个接口返回空数据、拒绝、受保护状态而轮换身份、放宽地址检查或绕过限制。不得将未知加密状态当作明文，不提取/复制认证或 DRM 密钥，不将红果匿名/账号身份用作番茄身份。

## 现有播放器可复用部分及风险

以下均为本分支起点代码的静态核对。

1. `NativeBridge` 的黄果路径和 `PlayLauncher` 提供独立来源启动播放器的结构参考。`PlaybackPlaylist` 已有有界队列、分季和 Binder 载荷约束。
2. `LibraryStore.series/episode` 和 `PlaybackPlaylist.series/episode` 重新构造 JSON，不能靠 UI 增加一个 `source` 字段就认为来源能一直保存。任意数字前缀也没有天然无冲突保证。
3. `PlaybackSources.registerInitial/resolve/resolvePlayback/recover` 默认会进入现有红果取源或回退。新来源的首播、切集、重试、预取、缓存都需明确分流，不能只传首集 URL。
4. `PlayerActivity` 的弹幕路径使用现有红果服务；浏览器投屏、DLNA、下载等还有自己的取源路径。新来源未支持的功能必须显式禁用，避免将另一来源的标识发送到这些服务。
5. `AppMediaSource` 不是仅明文解析器，它会调用现有受保护媒体处理逻辑。新来源不能在未检查播放权限和明文状态前直接复用。
6. `SearchClient` 已使用 `aid=1967` 的番茄形态注册/搜索参数，但其用途是现有搜索且存储键为 `hongguo_anonymous_search_v1`。这不证明它可直接充当独立番茄视频会话。
7. `NetworkGuard` 的 HTTPS、公网 DNS/IP 绑定、超时和逐跳校验可复用。新来源应约束到已核实的具体域名、路径和方法，不能把 `httpGet` 扩成任意代理。
8. 长 ID 在 Java 和 JavaScript 中均应保留为字符串。片源需核对请求与响应的剧集/分集身份、时长、尺寸、编解码和可访问状态。

## 有限的线上只读核对

- 红果官网真人剧目录和第一部剧的单集详情页能够返回 HTML。这只验证网页可达，不是媒体实播。
- 对静态确认存在的番茄 `POST /novel/player/video_model/v1/` 做了一次无登录公开请求，返回 HTTP 200、正文 0 字节。它既不是有效片源，也不足以确定鉴权方式、请求必填项、主链选择或所有网络环境中的行为。
- 该探测没有使用用户账号、设备标识或媒体密钥，没有登记身份或重试绕过服务器结果。未将签名媒体地址写入仓库。

## 新来源至少需要的新增回归

- 正常授权明文模型、缺少/错误加密状态、锁定或付费、错误身份、空正文和格式错误。
- 超长 ID、错误/未知编解码、非法域名/重定向、超大响应和超大剧集队列。
- 超时、取消、过期响应、返回/重进、快速切集、预取、缓存恢复。
- 每一类番茄失败都不得调用红果身份、取源、弹幕或账号路径。

APK 的更完整静态覆盖、调用链和未覆盖部分见同目录后续报告；所有结论以可核实证据为准。
