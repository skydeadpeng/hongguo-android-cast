# Android 红果播放排查与兼容性防护

本次排查日期：2026-11-11。基线为 `18240f15`，合并前对照为 `3e99c6c`。

## 已确认的现象

- 宿主可以读取红果官网目录与详情。随机选中《十八岁太奶奶驾到，重整家族荣耀第五部》，公开剧集编号 `7701935931787316286`，102 集；首集编号 `7701937936731737112`。官网标记首集 `protectedPlayback=true`，现有解析器按原策略拒绝把预览当作完整片源。
- API 30 x86_64 软件模拟器（TCG、无硬件加速）的当前版生产取源探针在官网目录、网页分集及匿名登记模型三个阶段超时。合并前版本的官网对照同样连接失败。这不能证明用户设备上的问题由本次合并导致。
- 当前 APK 的真实 `PlayerActivity` 可以通过生产播放桥打开上述首集，随后显示 `Index out of range`。测试未注入媒体地址；这只是播放器组件验证，首页未完成正常加载，不作为正常界面端到端验收。
- 在同一模拟器的 Android System WebView `83.0.4103.120` 内，无网络的签名探针立即复现该异常。调用栈为 `branchOf → le32 → writeUInt32LE → checkInt`。
- 最小实验显示缓冲区长度为 4，但该运行时把 `undefined >>> 0` 算成 `2147483647`，而 JavaScript 规范结果应为 0。省略偏移量的 32 位整数/浮点写入失败，显式偏移量 0 成功。BigInt 写入已有默认参数，不受此实验影响。

这是当前软件模拟器运行时的兼容性问题证据。尚未证明用户实体设备具有相同问题，也未证明全部视频的播放失败已经解决。

## 修改

仅为 `app-source-registered.js` 的四处数值写入补上显式字节偏移量 0：小端整数、大端整数、协议浮点字段和 SDK 字段。没有修改签名算法、请求字段、取源顺序、DNS、TLS、权限或用户数据。正常引擎的请求字节保持一致。

没有修改已有默认偏移量的 BigInt 写入，没有放松 Buffer 边界检查，也没有全局修改 JavaScript 运算或 Buffer 实现。

## 验证

- 同一真实 WebView：修前离线签名探针复现越界；显式偏移量对照连续 4 次签名成功，无网络请求。
- `node scripts/check-android-signer-offsets.cjs`：64 组通过，覆盖不同随机种子、时间分支、正常浏览器 Buffer 和明确标注的缺省偏移故障替身，比较 Node 与浏览器的完整请求字节。
- 独立审阅额外使用修前源码作为 Node 参考，与修后浏览器代码比较，64 组请求字节一致。故障替身不是 Android 实机验收。
- `node scripts/check-webos-signer.cjs`：4 组签名对拍通过；`node scripts/check-webos-crypto.cjs`：14 项通过。
- `npm run check:android`：48 项和项目检查通过；`npm run build:android:ui` 成功。
- JDK 17 / SDK 35 / Gradle 8.9 的独立 QA 手机 Debug APK 编译成功，打包的六个前端资源与最终工作区逐字节一致。APK SHA-256：`dd28341887b2ff8f364330724aabef0869ac3f1c7326aeae28e9b67fe175d012`。编译成功不代表实际播放成功。
- 新回归检查自动纳入 `npm test` 的 `check-*.cjs` 扫描，并在 Android Debug 构建工作流中显式运行。签名器及 Android 前端变更会触发该构建。

旧完整媒体回归入口另有依赖/断言漂移，未宣称全套回归通过。没有用合成视频代替真实素材，也没有获得本轮完整媒体下载、画面解码或音画同步验收。

## 安装与数据保护

旧测试 APK 的 Debug 私钥不在本轮环境中。为保留原安装及其数据，后续 APK 验证使用独立测试包名 `io.github.jackotom.hongguo.android.playbackqa` 和独立 Debug 证书，不卸载原包，不把新证书包称作可直接覆盖升级的正式版本。
