tvNative 0.1.16 发行记录（2026-11-13）

背景
- 0.1.15（11-11 22:49 构建，551 真签名 Java 移植）当晚真网取流与模拟器播放验证通过。
- 11-13 用户报告 tvNative 无法播放。同 APK 与 git 构建产物逐字节一致（sha256 800c8f00…），
  排除本地改动；桌面/手机（JS 链）同网络正常。

根因（真网探针实测，Node/Java 双侧复现）
- 上游自 11-12 起对匿名注册设备做身份分级风控：
  - 传统 multi_video_model/v1/ POST：约 3/4 概率 HTTP 404；
  - 按集 video_tab GET：大概率 200 空 body（掏空）；
  - 单一形态成功率约一成，被拒身份对两种形态同拒（同身份 4 种 query 形态同涨同跌，
    query 字段集/cdid 均非变量，变量是注册身份本身）。
- JS 版（app-source.js）靠"video_tab 优先 + multi POST 兜底 + 进程内复用首个好身份"维持高成功率；
  0.1.15 Java 版 multi POST 优先、404 不触发任何恢复（仅空 200 走 video_tab），撞上被拒身份即失败。

修复（android/app/src/main/.../RegisteredPlaybackModel.java）
- 每集取流改为 video_tab GET 优先（current API），同身份 multi POST 兜底（Connection: close）；
- 空 200 与 HTTP 错误（含 404）均可恢复，业务拒绝/格式错误保持终态；
- 被拒身份在内存中轮换重注册，最多三个身份 × 两形态，身份纯内存不落盘（边界不变）；
- 重注册 client 不再关闭共享 registration transport（否则第三次身份轮换不可能发生，真网复现修复）。

验证
- 回归：android/tests/run-registered-playback-model-tests.sh 全过
  （16 组 222 项 + JS 投影 golden + dispatch harness；网络请求 0）。
- 真网探针（Mac 直连，真实剧集第一集 vid）：修复前 8 次 1 成；修复后 22 次中 19 成
  （83-90%；单身份命中 ~850ms，轮换一次 ~1.6-2.0s，两身份失败 ~1.3-2.0s 后按 APP_EMPTY_RESPONSE 终态）。
- 模拟器端到端（iptv_tv ATV64，安装 0.1.16 compatible 包）：首页红果主源加载正常、
  详情页开始观看后真实剧集画面连续播放（两次截图画面与字幕推进），STREAM_MUSIC 音量 0 全程静音。

边界与限制
- 上游身份分级为概率性：个别时段连续三个身份全被拒仍会失败（约 1/6~1/12），重试一次基本恢复；
  客户端无法根治，依赖上游窗口。
- 未改 phone/TV WebView 版（JS 已有三路由兜底）与桌面版；本轮仅 tvNative Java 链。
- 未验证真机 TV 盒子；发布 feed 与资产按 tvNative 独立版本线（versionCode 17）。
